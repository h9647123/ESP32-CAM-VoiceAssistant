# v0.4.31-cam 源码更新

本次从 v0.4.26 整合到 v0.4.31。详见 CHANGELOG 与 README，保留 MIT；依赖与字体仍遵循 THIRD_PARTY_NOTICES。

修复长思考/长 JSONL 历史读取和安全保存、公式分式/角标排版、灰色思考缓存、连续滚动余量和 CUSTOM IAT 连接期间音量条不刷新。CUSTOM IAT 现支持采音时上传并显示服务端的部分结果；需要兼容的增量 IAT 服务，旧的只返回最终结果的服务不会因此产生逐字结果。

验证范围：实际代码提取的长历史（70KB 单条、190 条反复保存、损坏保护）、108 个公式/Markdown 绘制行、15 组循环/绘制节奏滚动测试、IAT 快照/尾音/最终 ACK、3 秒等待下音量刷新回归。主机回归不代表实体字体清晰度或网络服务可用性。开发设备 v0.4.30 的真人录音已确认录音中持续更新且内容正确；v0.4.31 在开发 CAM 板已通过真人首次录音复核：音量立即跳动，文字持续更新；串口显示零 I2S/缓冲溢出、发送字节数与采集一致，收到最终 ACK。

公开构建使用无凭据 config.h.example，源代码不含个人对话、照片、录音和 Flash 备份。此提交没有部署服务器，也没有修改原版硬件。

公开空配置构建通过：Arduino ESP32 3.3.8，程序 2,851,627 字节（90%），静态全局内存 79,132 字节。定向测试及搜索/贴底回归均通过。

草稿编辑：单击 C 删除一个 UTF-8 字符，第一次删字重绘完成后 350 ms 内的第二次 C 清空本次全部语音草稿，保留候选照片；切换页面、其他按键或新录音会中断双击判断。

修正长对话下的双击边界：第一次删字可能发生较慢的完整重绘，双击计时不包含这次重绘的耗时；否则连续按下的第二次 C 会错误地变成另一次删字。主机测试加入 700 ms 重绘情形。


后续实机回归补充：长历史下第一次删字的完整重绘可能超过双击窗口，现排除第一次重绘耗时。收到部分识别结果或编辑草稿时复用未变化的历史排版，只重排草稿；通过历史内容/角色、思考状态、语言、宽度及照片信息的指纹检查，避免同长度修正或设置变化造成陈旧显示。主机回归与全量重排参考在 100 组草稿/搜索/错误变化中结果一致，100 条未变历史在 100 次增量更新中没有重复解析。

MENU 二选项短按 A 直接切换并保存，包括识别语言、界面语言、思考显示、拍照/语音提问、仅拍照、相机预览及 OFF/AUTO 搜索。普通二档思考开关也直接切换；DeepSeek 四档思考以及视频分辨率、ASR 服务商、搜索服务商、模型/Provider 列表继续 B/C 编辑。时钟和 Web 开关保留原直接操作。

最新实机自动回归：CAM 与原版均通过连续双 C 清空整段及最后一个字、A 切换识别语言并恢复、亮度保持 B/C 编辑。原版 563 行历史下，连续草稿预览回执约 47—62 ms，旧实现约 797—953 ms；首次建立历史缓存仍约 797 ms。这是板端草稿绘制测量，不是端到端 ASR 延迟保证。
